## Overview

This project implements a complete, production-quality SPI hardware model at the Register Transfer Level (RTL) using Verilog HDL. The design explores the engineering trade-offs inherent in SPI slave design through two contrasting architectural approaches — an **oversampling (edge-detected) slave** and a **native SCLK-driven slave** — both verified against a common parameterized SPI master in full-duplex simulation.

The implementation is compliant with the IEEE 1364-2005 Verilog standard and was verified using Mentor Graphics ModelSim.

---

## Features

- ✅ **Full-duplex** simultaneous transmit and receive
- ✅ **All four SPI modes** supported (Mode 0, 1, 2, 3) via a single `mode` parameter
- ✅ **8-bit data width** (parameterizable)
- ✅ **FSM-based Master** with precise SCLK synthesis and CS management
- ✅ **Two slave architectures** with independent verification testbenches
- ✅ **CPHA=0 MSB preloading** handled correctly in both architectures
- ✅ **Modular design** — master and slave can be independently tested or integrated

## SPI Protocol Background

SPI is a synchronous, full-duplex, serial communication protocol widely used in embedded systems to connect microcontrollers with peripheral ICs such as ADCs, DACs, Flash memory, and sensors. It operates on a single-master, multi-slave topology.

### Signal Definitions

| Signal | Direction | Description |
|--------|-----------|-------------|
| `SCLK` | Master → Slave | Serial clock generated by the master |
| `MOSI` | Master → Slave | Master Out Slave In — data from master to slave |
| `MISO` | Slave → Master | Master In Slave Out — data from slave to master |
| `CS`   | Master → Slave | Active-low Chip Select — selects the target slave |

### SPI Modes (CPOL & CPHA)

The `mode` parameter is a 2-bit value `{CPOL, CPHA}` that configures clock polarity and phase:

| Mode | CPOL | CPHA | Idle Clock | Sample Edge | Shift Edge |
|------|------|------|------------|-------------|------------|
| 0    |  0   |  0   | Low        | Rising      | Falling    |
| 1    |  0   |  1   | Low        | Falling     | Rising     |
| 2    |  1   |  0   | High       | Falling     | Rising     |
| 3    |  1   |  1   | High       | Rising      | Falling    |

The logic `SCLK == ^mode` (XOR of CPOL and CPHA) is used throughout the RTL to dynamically determine the sampling vs. shifting edge, allowing a single codebase to handle all four modes without conditional rewriting.

## Architecture

### Master Module

**File:** [`MASTER.v`](MASTER.v)

The master is built around a **20-state Finite State Machine (FSM)** that tightly orchestrates every phase of an SPI transaction:

```
S0 (IDLE) → S1 (WAIT for data valid) → S2 (LOAD/PREPARE) → S3–S18 (16 SCLK half-cycles for 8-bit transfer) → S19 (DONE)
```

**State-by-state behavior:**

| States | Name | Description |
|--------|------|-------------|
| `S0` | IDLE | CS held high; SCLK driven to `mode[1]` (CPOL idle value); waits for `transmit` |
| `S1` | WAIT | Awaits `d_valid` to ensure data is stable before loading |
| `S2` | LOAD | Loads `data_in` into shift register `tx`; preloads `MOSI` with MSB if `CPHA=0` |
| `S3–S18` | SHIFT | Toggles SCLK each state (16 edges = 8 bits); samples `MISO` on the sampling edge and shifts `MOSI` out on the shifting edge |
| `S19` | DONE | Asserts `done`; returns to IDLE or re-enters transaction loop |

**SCLK synthesis** is done by toggling `SCLK` every FSM state cycle within S3–S18. The expression `SCLK == ^mode` correctly identifies the sampling edge dynamically for all four modes.

### Slave Architecture 1 — Oversampling (Edge-Detected)

**File:** [`SLAVE1.v`](SLAVE1.v)

This architecture uses a **fast internal system clock (`CLK`)** to oversample the incoming `SCLK` signal. A dedicated 1-bit register `t` captures the previous state of `SCLK`, enabling detection of rising and falling edges:

```verilog
assign rising  = (SCLK && (!t));   // SCLK went 0 → 1
assign falling = (!SCLK && t);     // SCLK went 1 → 0
```

All serial logic — sampling `MOSI` into `rx`, shifting `MISO` out from `tx`, and counting completed bit-pairs — executes within the safe, synchronous `CLK` domain. The module counts **16 SCLK transitions** (2 edges × 8 bits) and asserts `done` when `count == 16`.

**Reset behavior:** The slave resets on either the system `reset` signal or when `CS` goes high (de-selection acts as a reset).

**Trade-off:** All logic is within a single clock domain (safe from metastability during operation), but the effective maximum SPI frequency is bounded by the internal clock rate, and there is inherent sampling latency.

---

### Slave Architecture 2 — Native SCLK-Driven

**File:** [`SLAVE.2v`](SLAVE.2v)

This architecture eliminates the internal clock entirely. The slave's shift registers are clocked **directly by the master's `SCLK`**, using two separate `always` blocks to cover both clock edges:

- `always @(posedge SCLK or posedge load)` — handles one class of operations
- `always @(negedge SCLK or posedge load)` — handles the complementary class

The `load` signal (tied to `CS` assertion in the integration testbench) is used as an **asynchronous initialization trigger**, solving the critical CPHA=0 MSB preloading problem: the transmit register is preloaded with `data_in[7]` onto `MISO` at the moment `load` is asserted — before any SCLK edge arrives.

**Trade-off:** No sampling latency and inherently aligned with the SPI bus timing, but the clock domain crossing (SCLK domain → system domain) for the final assembled byte must be handled externally for real hardware synthesis.

## Module Interface Reference

### MASTER

```verilog
module MASTER(
    input  transmit,    // Start transaction
    input  MISO,        // Serial data from slave
    input  CLK,         // System clock
    input  reset,       // Synchronous reset
    input  d_valid,     // Data-valid handshake signal
    input  [7:0] data_in, // Parallel data to transmit

    output reg MOSI,    // Serial data to slave
    output reg SCLK,    // Generated serial clock
    output     CS,      // Active-low chip select (high = IDLE)
    output     done,    // Transaction complete pulse
    output reg [7:0] rx // Received parallel data
);
parameter mode = 2'd3; // {CPOL, CPHA} — default Mode 3
```

### SLAVE1

```verilog
module SLAVE1(
    input  MOSI,        // Serial data from master
    input  SCLK,        // Serial clock from master (oversampled)
    input  CS,          // Active-low chip select
    input  reset,       // Synchronous reset
    input  CLK,         // Fast internal system clock
    input  [7:0] data_in, // Parallel data to transmit

    output reg MISO,    // Serial data to master
    output     done,    // Transfer complete
    output reg [7:0] rx // Received parallel data
);
parameter mode = 2'd3; // {CPOL, CPHA}
```

### SLAVE2

```verilog
module SLAVE2(
    input  MOSI,        // Serial data from master
    input  SCLK,        // Serial clock — used directly as clock source
    input  CS,          // Active-low chip select
    input  load,        // Asynchronous load/init trigger
    input  [7:0] data_in, // Parallel data to transmit

    output reg MISO,    // Serial data to master
    output     done,    // Transfer complete
    output reg [7:0] rx // Received parallel data
);
parameter mode = 2'd3; // {CPOL, CPHA}
```

## Parameterization

All three modules share a common `mode` parameter encoded as `{CPOL, CPHA}`:

| `mode` value | Binary | SPI Mode |
|-------------|--------|----------|
| `2'd0`      | `2'b00`| Mode 0   |
| `2'd1`      | `2'b01`| Mode 1   |
| `2'd2`      | `2'b10`| Mode 2   |
| `2'd3`      | `2'b11`| Mode 3   |

To switch modes, change the `parameter mode` declaration in the module (or override it at instantiation). No other logic changes are required — the XOR-based edge selection adapts automatically.

## Verification & Testbenches

Five testbenches are provided, covering both unit-level and integration-level verification:

| Testbench | File | Description |
|-----------|------|-------------|
| Master Unit Test | [`MASTER_test.v`](MASTER_test.v) | Drives `transmit`, `d_valid`, and bit-by-bit `MISO` to verify master FSM, SCLK generation, CS assertion, and `done` output |
| Slave 1 Unit Test | [`SLAVE1_test.v`](SLAVE1_test.v) | Manually drives `SCLK` and `MOSI` into Slave 1; verifies edge detection, shift register, and `rx` assembly |
| Slave 2 Unit Test | [`SLAVE2_test.v`](SLAVE2_test.v) | Drives `SCLK`, `MOSI`, and `load`; verifies dual-edge operation and MSB preloading in all modes |
| Full-Duplex Integration 1 | [`SPI1_test.v`](SPI1_test.v) | Connects Master + Slave 1; uses separate `CLK_M` (10 ns period) and `CLK_S` (4 ns period) for realistic oversampling ratio |
| Full-Duplex Integration 2 | [`SPI2_test.v`](SPI2_test.v) | Connects Master + Slave 2; `load` is asserted concurrent with `d_valid` to preload slave before first SCLK edge |

**Sample data vectors used across testbenches:**
- Master transmits: `8'b10110011` (`0xB3`)
- Slave transmits: `8'b11001010` (`0xCA`)

All four SPI modes were individually verified for each testbench to confirm correct idle polarity, sampling/shifting edge assignment, MSB preloading, and full-word integrity.

## Design Trade-offs: Architecture 1 vs Architecture 2

| Aspect | Slave Architecture 1 (Oversampling) | Slave Architecture 2 (Native SCLK) |
|--------|--------------------------------------|--------------------------------------|
| **Clock source** | Internal fast `CLK` | External `SCLK` from master |
| **Clock domain** | Single (safe, synchronous) | SCLK domain (async to system) |
| **Max SPI freq** | Limited by `CLK` rate | Limited by SCLK directly |
| **Latency** | 1–2 CLK cycles per SCLK edge | Zero — direct clocking |
| **CPHA=0 preload** | Handled on first count cycle | Handled asynchronously via `load` |
| **CDC hazard** | Managed by oversampling | Exists at the output boundary |
| **Complexity** | Higher (edge detection logic) | Lower (simpler shift logic) |

---

## Clock Domain Crossing Considerations

**Slave Architecture 1:** The oversampling approach confines all logic to the internal `CLK` domain. However, since `SCLK` is an asynchronous input being sampled, the `t` register (used for edge detection) is technically a 1-FF synchronizer — a 2-FF synchronizer would be more robust for synthesis.

**Slave Architecture 2:** The shift registers operate in the `SCLK` clock domain. When the assembled `rx` byte and the `done` flag are read by a system operating on a different clock, a multi-stage dual-FF synchronizer or an **asynchronous dual-clock FIFO** is required to safely cross this boundary. This is a necessary addition before physical ASIC/FPGA synthesis.

## Future Work

- **Metastability hardening:** Add explicit 2-FF synchronizer chains for the `SCLK` input in Slave 1, and for `done`/`rx` outputs in Slave 2, to make both architectures synthesis-safe.
- **Multi-slave support:** Parameterize the master with a slave-count input and integrate an N-to-1 active-low chip select decoder to support multi-peripheral topologies.
- **FIFO integration:** Add dual-clock asynchronous FIFOs at the data boundaries of Slave 2 to enable continuous streaming and clean clock domain separation.
- **AMBA APB/AHB wrapper:** Wrap the SPI core with a standard bus interface for direct plug-and-play integration into ARM Cortex-M based SoC designs.
- **Formal verification:** Apply property-based formal verification (e.g., using SymbiYosys) to prove functional correctness of the FSM across all reachable states.
